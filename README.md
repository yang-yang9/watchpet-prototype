# 玩法方向原型（2026-10-11）

**这份原型是用来「定方向」的,不是用来定细节的。** 定了方向再写 spec,写完 spec 再写代码。

打开 `index.html` 就行——纯静态单文件,没有构建步骤,没有外部依赖,发到手机上也能看。

```bash
# 本地起个服务也行,但不必须
python3 -m http.server --directory docs/prototypes/directions
```

> 宠物名和 App 名**都还没定**。原型里的「小团」是临时代号,别基于它做品牌或文案判断。

## 三个方向

| | 一句话 | 为什么会回来 | 现有代码能用多少 | 要新美术吗 |
| --- | --- | --- | --- | --- |
| **A · 镜子** | 它反映你今天的状态 | 好奇它今天在干什么 | 几乎全部 | 不要 |
| **B · 同行** | 你们每天一起做一件事 | 一天一个闭环 + 攒本子 | 大约一半 | 不要 |
| **C · 它自己的生活** | 它自己过日子,顺路带东西回来 | 收集 + 它刚回来的通知 | 少 | 要,量最大 |

三个方向**结构上**不一样,不是同一个玩法的三种皮:A 里主动的是你,B 里它提议你决定,C 里它自己推进。
每个方向都给了手表和手机的核心画面,都能点。页面右侧四段说明写了玩法循环、为什么会回来、技术前提、风险。

## 风格是另一条轴

换风格只换颜色和字体,**不动布局**——这样「玩法好不好」和「长得好不好看」能分开判断。
三套：柔纸（暖、米色、衬线）、夜色（深色,手表上最省电）、点阵（单色、等宽、硬边）。

## 每一屏都有地址

```
index.html?dir=b&screen=today&style=ink
index.html?dir=a&screen=trends&style=paper&freeze=1
```

`dir` = `a|b|c`,`style` = `paper|ink|retro`,`screen` = 该方向任意一屏的名字（手表和手机的都认）。
`freeze=1` 把每个动作通道停在**幅度峰值**那一帧,所以同一个 URL 两次截图逐像素相同,
可以用来比对改动；也正好回答「这个动作在画面上看得出来吗」——停在起点那一帧和完全没动长得一样。

可寻址不只是为了截图:发链接能直接指到「就那一屏的那个按钮」。

## 宠物是内联 SVG,不是图片

整个原型**一张图片都没有**。宠物是 SVG + CSS 变换,四种姿态（idle / playful / sleepy / calm）
加四个动作通道（位移、旋转、缩放、眨眼）与一个作用部位（body / ears / eyes）。

这是刻意的:现在没有任何美术资源,用 SVG 才能诚实地回答「不加新资源能表达到什么程度」。
通道和幅度照 `docs/superpowers/specs/2026-10-10-pet-personality-design.md` 的配方表抄,
所以原型和已写好的规则层说的是同一件事。长期的渲染路线见 `docs/design/pet-render-roadmap.md`。

## 原型里刻意没有的东西

都是产品原则,不是省事:

- 没有任何内部数值——没有性格雷达图、没有健康评分、没有进度百分比。方向 B 的进度条只有形状和一句「快到了」。
- 缺席、步数低、睡得少都不扣任何东西。方向 B 的空格子明说了「只是没有照片」。
- 不声称识别情绪,不做任何健康判断。

## 这台机器验不了什么

Linux,没有 Xcode,没有 Apple 设备。所以:

- **已验**:3 个方向 × 3 种风格,加上全部 21 屏（手表 12 + 手机 9）在 Chromium 下的
  静态渲染,用 `Tools/shoot.sh` 截图逐张看过。查出并修掉三处：方向 C 的 tabbar 没钉在
  屏幕底边、技术前提里漏了一对没渲染的 `**`、息屏常亮那屏的时间压在底部说明上。
- **没验**:**动起来的样子**。截图是静态的,`freeze=1` 看的是单帧——动画的节奏、
  缓动曲线、会不会晃得难受,这台机器上看不到。
- **没验**:真机上的触感、常亮表现、耗电、复杂功能的真实刷新频率。
  手表框是按 46mm 的 208×248pt 画的,但那只是尺寸对,不等于观感对。

真机相关的判断只能由你在设备上做。
